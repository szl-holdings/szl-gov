# Per-call price catalog

[`catalog.yaml`](catalog.yaml) is the canonical list of per-call (x402) prices for
the SZL estate: every path the Cloudflare Monetization Gateway charges, with its
host, path prefixes, HTTP methods, audience, scheme, atomic USDC price and the
gateway rule's own description. It is the only hand-edited per-call price list.
Everything else is generated from it by [`tools/pricing_catalog.py`](../tools/pricing_catalog.py):

| Output (`pricing/generated/`) | Where it is published |
|---|---|
| `x402-pricing.json` | `szl-holdings/a11oy` `.well-known/x402-pricing.json`, served free at https://a-11-oy.com/.well-known/x402-pricing.json |
| `per-call-table.html` | the "Per-call API prices (x402)" section of a-11-oy.com/pricing (`a11oy` `pages/pricing.html`) |
| `per-call-table.md` | README and docs snippets, such as the table below |
| `rule-count.md` | the one-line rule count quoted in READMEs |

The catalog covers per-call gateway prices only. Subscription and enterprise tiers
(a-11-oy.com/pricing, `governance-as-code/pricing/PRICING.md`) are not per-call
prices and are not listed here.

## Commands

```bash
# Does the catalog agree with a rules export? (exit 0 agree, 1 disagree, 2 unreadable)
python3 tools/pricing_catalog.py check \
  --rules pricing/snapshots/monetization-rules-2026-11-06.redacted.json \
  --changes pricing/snapshots/monetization-changes-2026-11-06.json

# Regenerate pricing/generated/ (or --check that the committed files are current)
python3 tools/pricing_catalog.py generate

# Replace the generated region of a page or README in another repository checkout
python3 tools/pricing_catalog.py sync ../a11oy/pages/pricing.html --format html

# Redact the estate-probe user-agent list from a raw export before committing it
python3 tools/pricing_catalog.py redact raw-export.json -o pricing/snapshots/<name>.redacted.json

# Canonical formatting of catalog.yaml (or --check)
python3 tools/pricing_catalog.py fmt
```

`tests/test_pricing_catalog.py` runs the check against the committed export,
requires the generated files and the table above to be current, and changes one
fact at a time in a copy of the export (price, description, host, path,
audience, pay-to address, exemption list, a new rule, a re-enabled rule) to
prove each kind of drift is reported.

## When the gateway rules change

1. Export the rules for every zone (the Cloudflare dashboard or the
   Monetization Gateway rules API) and record any enable/disable changes made
   after the export in a change log of the same shape as
   `snapshots/monetization-changes-2026-11-06.json`.
2. Redact the export with `redact`, commit it under `snapshots/`, and run
   `check` against it. Every disagreement is a line to fix in `catalog.yaml`.
3. Edit `catalog.yaml` until `check` passes, then run `generate`.
4. Publish the outputs: copy `generated/x402-pricing.json` to
   `a11oy/.well-known/x402-pricing.json`, `sync` the table into
   `a11oy/pages/pricing.html`, and update the README snippets that embed
   `per-call-table.md` or `rule-count.md`.

Where a page or document needs a price that no enabled rule defines, the catalog
lists it under `not_offered_yet` with no price. It never invents one.

## Evidence

- Rules: the Monetization Gateway rules API export of 2026-11-06 for the zones
  a-11-oy.com, a11oy.net and szlholdings.com (`snapshots/`, see
  [`snapshots/README.md`](snapshots/README.md)).
- Changes: the change log of the three rules disabled at 16:27 UTC under the
  owner's policy (charge API and MCP hosts only).
- Payment terms (network `eip155:8453`, USDC asset, `maxTimeoutSeconds`): the
  x402 v2 `PAYMENT-REQUIRED` headers the gateway returned to the estate
  coordinator's 2026-11-06 edge scans. The pay-to address is also on every rule.
- HTTP methods: the export records no method selection. Cloudflare documents
  that a rule charges GET by default (Monetization Gateway docs, "Monetization
  rules", updated 2026-09-30), so the catalog lists GET and marks POST unverified.

## Proof boundary

`check` proves that the catalog agrees with the export it is given. It does not
prove that the export is current (the dashboard can change at any time), that
any payment has settled, or that an origin serves a caller who paid. The rule
expressions are evaluated by a small interpreter that implements only the
operators these rules use (`starts_with`, `eq`, `contains`, `wildcard`,
`cf.client.bot`, `and`/`or`/`not`); any other construct makes the check fail
rather than guess.
